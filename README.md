# BugalterSZ

Аукцион STALCRAFT, бухгалтерия и заметки в одном приложении на данных EXBO API.
Работает на **Cloudflare Pages** (сайт + Functions) и базе **Cloudflare D1**. Локальный сервер больше не нужен.

## Что где лежит

```
public/        сайт: index.html, app.js, styles.css, bg.svg (фон), shared/money.js
functions/     Cloudflare Pages Functions: один файл api/[[path]].js принимает все запросы /api/*
src/           серверный код: маршруты, авторизация, клиент EXBO, сканер, оценка лотов (deals.js)
schema.sql     схема базы D1
wrangler.toml  привязка базы и настройки
scripts/       build-catalog.js — собирает public/catalog.json (каталог предметов)
test/          тесты (npm test)
```

## Деплой на Cloudflare Pages

Нужны: аккаунт Cloudflare (бесплатный подойдёт), Node.js 20+ и ключи EXBO (https://exbo.net/oauth → создать приложение).
Все команды выполняются в папке проекта.

**1. Установка и вход**

```
npm install
npx wrangler login
```

**2. База данных**

```
npx wrangler d1 create bugalter-sz
```

Команда выведет `database_id`. Вставь его в `wrangler.toml` вместо `ВСТАВЬ-СЮДА-database_id`. Затем создай таблицы:

```
npm run db:remote
```

**3. Проект Pages и первый деплой**

```
npx wrangler pages project create bugalter-sz --production-branch main
npm run deploy
```

`npm run deploy` сначала скачивает каталог предметов (`public/catalog.json`), потом загружает сайт и функции.
Адрес сайта будет вида `https://bugalter-sz.pages.dev`.

**4. Ключи EXBO**

```
npx wrangler pages secret put EXBO_CLIENT_ID --project-name bugalter-sz
npx wrangler pages secret put EXBO_CLIENT_SECRET --project-name bugalter-sz
```

Секреты начинают действовать со следующего деплоя: выполни `npm run deploy` ещё раз.
Без ключей сайт работает в **демо-режиме** на выдуманных лотах (жёлтая плашка «Демо-данные»).

**Вариант через GitHub (рекомендуется).** Залей проект в репозиторий, и Cloudflare будет сам пересобирать сайт при каждом пуше.

1. Создай базу и таблицы (шаг 2 выше), вставь настоящий `database_id` в `wrangler.toml` и закоммить его.
   Это не секрет. Пока в проекте есть `wrangler.toml`, Cloudflare берёт привязку базы оттуда, а не из панели.
2. В панели Cloudflare: Workers & Pages → Create → Pages → Connect to Git → выбери репозиторий.
3. Build command: `npm run build`, build output directory: `public`.
4. После создания проекта: Settings → Variables and Secrets → добавь секреты `EXBO_CLIENT_ID` и `EXBO_CLIENT_SECRET`,
   потом запусти передеплой (Deployments → Retry deployment или новый пуш).

Перетаскивание папки в панели (Direct Upload) не подойдёт: оно не собирает папку `functions`.

**Локальная проверка** (по желанию): `npm run db:local`, затем `npm run dev`. Ключи для локального запуска кладутся
в `.dev.vars` (образец: `.dev.vars.example`).

## Как работает сканер на Cloudflare

Раньше сканер крутился в фоне на сервере. У Cloudflare Pages постоянно работающего процесса нет, поэтому
сканирование идёт «тиками»: пока открыта вкладка «Аукцион», страница раз в 3 секунды вызывает `POST /api/auction/tick`.
Один тик обрабатывает пачку предметов (`SCAN_BATCH`, по умолчанию 10): сначала те, у которых есть лоты, потом очередная
порция каталога по кругу. Блокировка в базе не даёт нескольким вкладкам сканировать одновременно и держит темп
запросов в пределах `RATE_LIMIT_PER_MIN`.

Что из этого следует:

- **Лента и выгодные лоты обновляются, только пока кто-то держит страницу аукциона открытой.** Когда все вкладки закрыты, сканирование стоит.
  Хочешь, чтобы шло постоянно: задай секрет `TICK_SECRET` и дёргай `POST https://твой-сайт/api/auction/tick` с заголовком
  `X-Tick-Secret: <секрет>` по расписанию (например, через бесплатный cron-job.org).
- **Первый круг по каталогу долгий** (тысячи предметов × регионы). Прогресс виден на странице, пока лента пуста.
- **Лента отстаёт от игры** на 10–20 минут: так отдаёт сам API.
- **Лимиты бесплатных планов Cloudflare.** Free: 50 подзапросов и 10 мс процессорного времени на один вызов, 100 тысяч записей
  в D1 в сутки. Если тики падают с ошибкой лимита, уменьши `SCAN_BATCH` (например, до 5). Если сайт долго стоит
  открытым, суточный лимит записей в D1 может кончиться, тогда аукцион до следующих суток перестанет обновляться, а бухгалтерия и заметки
  тоже могут не сохраняться. Для постоянной работы удобнее платный план Workers ($5 в месяц).
- Хэширование паролей идёт через PBKDF2 (в Workers нет scrypt). Если на бесплатном плане вход падает с ошибкой CPU,
  поставь переменную `PBKDF2_ITER=30000`.
- Прежние аккаунты и записи из `data/db.json` старой версии не переносятся: на новом сайте нужно зарегистрироваться заново.

## Как считаются выгодные лоты

Для каждого предмета с выкупом берётся история продаж (до 400 последних за 14 дней), и цена лота **за штуку**
сравнивается с **медианой** продаж.

**Сравнение идёт по качеству и заточке.** Лот сравнивается только с продажами того же предмета, у которых совпадает
качество (обычный … легендарный) и заточка (+0 … +15):

- сначала берутся продажи с **тем же качеством и той же заточкой**, если их хотя бы `DEAL_MIN_SAMPLES` (5);
- если точных продаж мало, окно расширяется **только вниз по заточке**, максимум на `DEAL_PTN_WINDOW` (2) уровня:
  +5 можно сравнить с +4 и +3, но не с +6. Продажи с меньшей заточкой стоят дешевле, так что такая медиана
  может только занизить справедливую цену и не рождает ложных «выгодных» лотов. В карточке видно, с чем сравнили
  («Редкий +3…+5»);
- если и так продаж не хватает, лот не оценивается (лучше пропустить, чем показать ложную выгоду);
- у предметов без качества (аптечки, патроны) сравнение идёт по общей медиане.

В рекомендации попадает лот, если:

- он дешевле медианы минимум на 15% (`DEAL_MIN`);
- в сравнении хотя бы 5 продаж (`DEAL_MIN_SAMPLES`);
- экономия не меньше 1000 ₽ (`DEAL_MIN_SAVINGS`).

Лоты дешевле 10% медианы отбрасываются: почти всегда это ошибка продавца или неподходящая история.

На странице предмета можно выбрать качество и заточку: покажется медиана именно этой группы, график цен и лоты с такими
параметрами. Подсказка на значке скидки («−23%») объясняет, с какой медианой сравнивали.

## Настройки

Не секретные настройки лежат в `[vars]` файла `wrangler.toml`, секреты задаются командой `wrangler pages secret put`.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `EXBO_CLIENT_ID`, `EXBO_CLIENT_SECRET` | пусто | ключи EXBO (секреты). Или `EXBO_TOKEN` — готовый токен |
| `REGIONS` | `ru,eu` | регионы аукциона: ru, eu, na, sea |
| `DEAL_MIN` | `0.15` | минимальная скидка от медианы |
| `DEAL_MIN_SAMPLES` | `5` | минимум продаж для сравнения |
| `DEAL_MIN_SAVINGS` | `1000` | минимальная экономия, ₽ |
| `DEAL_PTN_WINDOW` | `2` | на сколько уровней заточки вниз можно расширять сравнение (0 — только точная заточка) |
| `HISTORY_PAGES` | `2` | сколько страниц (по 200) истории грузить предметам с качеством |
| `HISTORY_PRICE` | `auto` | цена в истории продаж: `unit` (за штуку), `total` (за лот) или `auto` |
| `SCAN_BATCH` | `10` | предметов за один тик |
| `RATE_LIMIT_PER_MIN` | `240` | лимит запросов к EXBO в минуту |
| `TICK_SECRET` | пусто | секрет для запуска тиков по расписанию |
| `DEMO` | `0` | `1` — принудительно демо-режим |
| `PBKDF2_ITER` | `100000` | число итераций хеша пароля (10000–100000) |

## Фон

Фоновый рисунок лежит в `public/bg.svg` (линии рельефа и знак радиации), его заметность задаёт переменная
`--art-opacity` в начале `public/styles.css` (0 — выключить). Свою картинку можно положить рядом и поменять путь
в правиле `body::before`.

## Проверка

`npm test` запускает тесты: разбор сумм, оценка лотов по качеству и заточке, сквозная проверка API на демо-данных.
