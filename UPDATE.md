# Безопасность регистрации и входа (ноябрь 2026)

Что изменилось: пароль от 10 символов без «обязательных цифр», запрет частых паролей и своего ника, проверка по базе утечек
(Have I Been Pwned, уходят только 5 символов SHA-1), поле «повторите пароль» и кнопка «показать», «перец» для хеша,
пересчёт старых хешей при входе, лимит регистраций с IP и блокировка при подборе пароля, защита от ников-«двойников»
(кириллица/латиница, `_ . -`) и служебных ников, кука `__Host-sz_sid` по https, не больше 10 сессий на аккаунт,
на странице аккаунта: смена пароля, «выйти на всех устройствах» и удаление аккаунта. Заголовки: HSTS, `object-src 'none'`,
`form-action 'self'`, Permissions-Policy, COOP; браузерные запросы с чужого сайта (`Sec-Fetch-Site: cross-site`) отклоняются.

## Как применить

1. Распакуй архив поверх `C:\BugalterSZ` с заменой файлов. Если в проекте больше нет `server/` и `deploy/`, ничего страшного.
2. `npm install`, затем `npm test` (должно быть 40 из 40; на Windows тесты `turso` и `server` тоже должны проходить).
3. **Сначала зарегистрируй свой ник на сайте**, а потом обнови схему: задай `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` и выполни `npm run db:turso`.
   Скрипт создаст новые таблицы и занесёт «скелеты» уже существующих ников (по ним ники-двойники, например `Кronix404` с русской К, уже не зарегистрируются).
   Если не обновить схему, сайт работает, но блокировки, лимит регистраций и защита от двойников молча отключены.
4. По желанию включи «перец» (рекомендуется): сгенерируй секрет `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`,
   добавь его в Cloudflare как **Secret** `PASSWORD_PEPPER` и сделай передеплой. Пароли получат перец при следующем входе владельцев.
   **Сохрани значение в надёжном месте.** Если потерять или поменять секрет, хеши с перцем перестанут проверяться и войти не сможет никто, кого уже обновили.
5. `git add -A`, `git commit -m "Безопасность регистрации"`, `git push`.

## Новые настройки (необязательные)

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `PASSWORD_PEPPER` | пусто | секрет для HMAC пароля (Secret) |
| `REG_PER_HOUR` | `5` | регистраций в час с одного IP |
| `HIBP_OFF` | пусто | `1` отключает проверку паролей по базе утечек |

Блокировка входа: 5 неудач с одного IP на один ник (потом пауза 30 с, 1 мин, 2 мин … до 15 мин) и 20 неудач на ник со всех IP вместе.

# Что нового в этой версии

1. **Чёрный список предметов.** Мусор не сканируется и не попадает в «Новые» и «Выгодные» лоты, но находится поиском.
   По умолчанию скрыты категории `misc`, `supply/food`, `supply/drink`, `other` (кроме `other/skins`). Список правится в

   вернуть можно в аккаунте.
2. **Оружейные модули** сравниваются по названию в кавычках («Снайпер», «Пробойник» …), затем по качеству. На странице
   предмета появился фильтр по модулям.
3. **Аккаунт:** клик по нику справа вверху. Ник, последний вход, дата регистрации, неактивная кнопка подписки, скрытые предметы.
4. **Шапка:** название слева, рядом значки «поддержать автора» и «поддержка» (ссылки задаются в `LINKS` в `public/app.js`).
5. **Бухгалтер:** на странице только операции текущего дня, в 00:00 по UTC+3 день закрывается и уходит в личный архив
   (кнопка «Архив» открывает панель слева). «Итог дня» считается за день по UTC+3.

`/api/auction/module-samples` и пришли мне текст ответа: по нему я точно настрою чтение.


## Google Search Console

1. Открой https://search.google.com/search-console → «Добавить ресурс» → «Префикс URL» → адрес сайта.
2. Выбери подтверждение «HTML-тег», скопируй тег `<meta name="google-site-verification" content="...">`
   и вставь его в `public/index.html` вместо закомментированной заготовки в `<head>`. Запушь, дождись деплоя,
   нажми «Подтвердить».
3. «Файлы Sitemap» → добавь `sitemap.xml`. Потом «Проверка URL» → вставь адрес главной → «Запросить индексирование».
4. Если у сайта свой домен (не `bugalter-sz.pages.dev`), замени адрес в `public/sitemap.xml` и `public/robots.txt`.
